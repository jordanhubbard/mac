# Close the tokenhub dark spot: consume its decision feed (do NOT merge it)

**ADR 0001 stage 5.** TokenHub stays a separate Go service — it is mature infra
(Thompson-sampling router, AES-256-GCM/Argon2id vault, Temporal workflows) and a
Python rewrite would be the ACC "too complicated" failure. The actual problem is
that its routing decisions are invisible to the agent.

TokenHub already broadcasts routing events over an SSE event bus
(success/error/escalation/health/model-selection) and renders a live decision
feed in its admin UI. mac just doesn't consume it.

## Acceptance Criteria

- [ ] mac subscribes to TokenHub's SSE decision feed (URL from `TOKENHUB_URL`).
- [ ] Each routing decision is recorded as a `tokenhub.route.*` observation in
      mac's observability and, where correlatable, attributed to the agent/turn
      (correlation id or idempotency key) that caused it.
- [ ] An operator (and the agent itself) can answer "why am I on provider X
      model Y right now?" from mac observability — failover, Thompson sample,
      budget/health filter, or in-band `@@tokenhub` directive.
- [ ] Surfaced in the dashboard's observability/hermes views.

## Notes

This can proceed in parallel with hu-02..hu-04 (no hard dep). Pairs naturally
with hu-01's `hermes.provider.resolved` events to give one coherent provider
story per turn.
