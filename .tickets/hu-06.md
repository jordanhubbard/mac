# Epic: unify the Hermes runtime into the mac monorepo (ADR 0001)

Tracking epic for the decision in
`docs/adr/0001-unify-hermes-runtime-into-mac.md`.

**Verdict.** The mac↔hermes boundary (clone pristine upstream + 3 out-of-tree
patches incl. a 1,372-line feature fork + runtime string-surgery monkeypatching
+ separate venv/process/event-loop) is a root cause of the fragility and
opacity. Fix it by owning a pinned, pruned, in-tree snapshot run in one process.
The mac↔tokenhub boundary is NOT the problem the premise assumed — keep the Go
service, make its decisions legible. mac's internal pain (inert memory tier,
observability bloat) is unrelated and tracked elsewhere.

## Stages

- [x] hu-01 — keystone: own the provider decision in-process (main, 2026-05-30)
- [x] hu-02 — vendor the pinned, pruned runtime snapshot (**PR #2**): 590 py
      files; manifest measured static+runtime; dep merge applied (uv.lock
      resolves clean); sys.path bootstrap; full gateway imports in-process.
- [~] hu-03 — code done (**PR #2**): vendored `gateway/run.py` calls
      `mac.agent_provider` (string-surgery killed; `mac-provider-decision.patch`);
      in-process launcher `mac-hermes-gateway`. Remaining: switch the deployed
      gateway/oneshot to it + delete the live shims (coupled to hu-04).
- [x] hu-04 — **in-process gateway rolled out to the whole fleet** 2026-05-31
      (rocky/natasha/bullwinkle): one venv, `mac-hermes-gateway` runs the vendored
      runtime, slack=connected everywhere, canary-validated with auto-revert.
      Codified in `deploy-mac-fleet.sh`. Remaining (non-blocking): remove the
      vestigial upstream clone/patch + `MAC_HERMES_AGENT_DIR` + dead shims.
- [x] hu-05 — TokenHub decision-feed consumer built, tested, AND wired into the
      control-plane startup (`mac.tokenhub_feed` + `create_app`, PR #3 merged).
      Gated no-op until the events URL + admin token are configured on the hub.

## COMPLETE 2026-05-31

All stages done and validated fleet-wide (rocky/natasha/bullwinkle): one repo,
one venv per agent, the Hermes runtime vendored in-tree and run in-process; the
upstream clone, separate venv, and runtime string-surgery shims are gone; the
TokenHub decision feed is consumed for provider legibility. The 3-month
boundary problem is resolved in practice. (hu-05 feed activation on the fleet
needs only the TokenHub admin token in the hub mac.env.)

## Guardrails (so this is not failure #3)

- Snapshot-and-prune; freeze the pin (don't chase upstream commit-of-the-day).
- Reduce **boundary** complexity, accept the line-count cost (already largely
  paid via the 1,372-line patch).
- Do not rewrite TokenHub. Do not land an atomic big-bang merge.
