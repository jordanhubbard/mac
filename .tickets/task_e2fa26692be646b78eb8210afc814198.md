# Dashboard bearer token passed via `?t=` URL param leaks into server/proxy logs

## Why this exists

The dashboard bootstraps its API bearer token from a `?t=<token>` query
parameter on first load (deploy links hand out URLs of this shape):

`src/mac/ui/app.ts:987` (`bootstrapConnectionFromUrl`):

```js
const params = new URLSearchParams(window.location.search);
const t = params.get("t");
if (t) {
  sessionStorage.setItem(TOKEN_KEY, t);
  params.delete("t");
}
...
history.replaceState(null, "", newUrl);   // line ~1003: strips ?t= from the URL bar
```

The existing `history.replaceState` (line 1003) is good — it removes the token
from the **browser address bar and history**. But that does **not** cover the
places the token has already traveled by the time JS runs:

- **Server / reverse-proxy access logs.** The very first request to
  `GET /ui?t=<token>` is logged with the full query string by uvicorn and by any
  fronting proxy/load balancer before `replaceState` ever executes. On the rocky
  hub this is a real path: the hub binds `0.0.0.0:8789` (per `~/.mac/fleets.yaml`
  rocky entry, `control_bind_host: "0.0.0.0"`), so the dashboard — which can open
  shells into agents over AgentBus — is reachable across the tailnet over **plain
  HTTP**, and the credential lands in logs in cleartext.
- **`Referer` header** on any resource the initial `?t=` page requests before
  the rewrite.
- **Anything that captured the URL pre-rewrite** — browser network panel, crash
  reporters, screen-shares of the deploy link.

A bearer token in a log file is a reusable credential; this is a
credential-exposure bug, not just a cosmetic one.

## Design

Options, roughly in order of preference:

1. **Stop putting the token in the query string.** Hand it to the page via the
   URL **fragment** (`#t=<token>`) instead of `?t=`. Fragments are never sent to
   the server and never appear in access logs or `Referer`. The existing
   read-then-`replaceState` flow works the same against
   `window.location.hash`.
2. If query-param links must stay supported for back-compat, **treat any token
   seen in `?t=` as burned**: scrub it from access logs (don't log query strings
   on `/ui`) AND rotate/short-TTL such tokens so a leaked one is useless quickly.
3. **Require TLS** for any non-loopback dashboard bind so the token isn't also
   exposed on the wire (tracked partly by deploy hardening; cross-link
   [[deploy-port-drift-01]]).

Also audit the related `?api=` / `?u=` params (same block) — those are not
secrets but confirm nothing sensitive rides alongside.

## Acceptance Criteria

- A fresh deploy link no longer transmits the bearer token in a way that reaches
  uvicorn/proxy access logs (fragment-based, or query-logging suppressed +
  short-TTL tokens).
- `tests/ui/test_ui_shell.py` gains a case asserting the new bootstrap path
  reads the token without it surviving in `window.location.search`.
- Decision recorded on whether the non-loopback dashboard bind must be TLS-only.
