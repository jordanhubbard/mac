# Make task lifecycle transitions atomic with a domain-event outbox

Task transition paths commit core task state separately from history rows and external side effects such as workflow advancement and Beads synchronization. That makes lifecycle reconstruction fragile and forces future refactors to reason about partial updates scattered across methods.

## Acceptance Criteria

A task state transition commits task changes, lease changes, history, and side-effect intents in one transaction; workflow and Beads effects consume idempotent outbox records; tests prove claim/transition retry cannot leave a task without corresponding lifecycle history or queued side-effect intent.
