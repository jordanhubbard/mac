# Import the gateway in-process; delete the runtime string-surgery shims

**ADR 0001 stage 3.** Make the boundary disappear: run the vendored Hermes
gateway inside the mac process / event loop instead of as a separate venv
subprocess (`hermes gateway run --replace`).

## Strategy (measured in hu-02)

Hermes uses flat top-level absolute imports everywhere, so the vendored tree
goes on `sys.path` (`src/mac/_hermes/`) with **no import rewriting**. The work
here is: (1) merge dependency manifests, (2) `sys.path`-bootstrap the vendored
tree, (3) launch the gateway in-process, (4) delete the string-surgery shims.

**De-risked (PR #2):** with `mac.hermes_vendor.ensure_on_path()` + the
`hermes-gateway` extra installed, `gateway.run`, `gateway.session`,
`agent.conversation_loop`, `agent.agent_init`, and `plugins` all **import
in-process from the vendored tree** (test: `test_full_gateway_imports_in_process`).
So (1) and (2) are done; remaining is the in-process *launch* wiring + shim
deletion, which couples to hu-04 (the live deploy still uses the clone+patch
path until then, so the shims can't be deleted before the single-venv deploy).

## Acceptance Criteria

- [x] Vendored `gateway/run.py` resolves the provider via
      `mac.agent_provider.resolve_agent_provider` directly (hu-01), not via a
      shim — no code rewrites another file's source at runtime. Done (PR #2):
      `_mac_provider_decision()` is called inside `_resolve_runtime_agent_kwargs`
      and `_resolve_gateway_model` so every call site honors the override;
      captured as `deploy/hermes/mac-provider-decision.patch` (applies clean to
      upstream) for re-vendor reproducibility; no-op standalone. Tested by
      `test_vendored_gateway_honors_mac_provider_override`.
- [x] Delete `_apply_gateway_runtime_shim`, `_maybe_apply_gateway_runtime_shim`,
      and the slack-activation/home-channel string-surgery shims from
      `hermes_startup.py` (PR #4, merged): ~449 lines / 10 functions removed; the
      startup report is clone-free and derives from the owned `agent_provider`
      decision. Canary-validated on natasha, then converged on all three agents
      (self-test passes fleet-wide).
- [x] An in-process gateway entrypoint exists that mac can launch and observe.
      Done: `mac.hermes_gateway:main` (console script `mac-hermes-gateway`)
      bootstraps the vendored tree, logs the secret-free provider decision at
      start (dark-spot fix at launch), and delegates to the vendored
      `gateway.run.main`. Tested by `test_hermes_gateway_launcher_delegates_without_booting`.
      Remaining: point the oneshot executor at the vendored runtime in-process
      (currently still the separate-venv `hermes` path until hu-04).
- [ ] `mac.agent_provider.record_provider_decision` fires on every gateway/agent
      runtime resolution so provider behavior is attributable per turn.
- [ ] Tests cover in-process resolution; `/startup/hermes` reflects in-process
      runtime rather than filesystem-metadata inspection of a foreign checkout.
