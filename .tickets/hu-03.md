# Import the gateway in-process; delete the runtime string-surgery shims

**ADR 0001 stage 3.** Make the boundary disappear: run the vendored Hermes
gateway inside the mac process / event loop instead of as a separate venv
subprocess (`hermes gateway run --replace`).

## Acceptance Criteria

- [ ] Vendored `gateway/run.py` resolves the provider via
      `mac.agent_provider.resolve_agent_provider` directly (hu-01), not via a
      shim — no code rewrites another file's source at runtime.
- [ ] Delete `_apply_gateway_runtime_shim`, `_maybe_apply_gateway_runtime_shim`,
      and the slack-activation/home-channel string-surgery shims from
      `hermes_startup.py`; fold any needed behavior into the vendored gateway.
- [ ] An in-process gateway entrypoint exists that mac can launch and observe
      (single asyncio loop); the oneshot executor path uses the vendored runtime
      in-process rather than spawning a separate-venv `hermes`.
- [ ] `mac.agent_provider.record_provider_decision` fires on every gateway/agent
      runtime resolution so provider behavior is attributable per turn.
- [ ] Tests cover in-process resolution; `/startup/hermes` reflects in-process
      runtime rather than filesystem-metadata inspection of a foreign checkout.

## Notes

This is the ticket that actually delivers "one event loop, one process,
observable agent." Keep `multi-slack-mvp` behavior intact (it's now in-tree).
