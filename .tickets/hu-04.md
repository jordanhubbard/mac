# Single-venv deploy: stop cloning upstream Hermes; retire MAC_HERMES_AGENT_DIR

**ADR 0001 stage 4.** With the runtime vendored (hu-02) and imported in-process
(hu-03), the deploy no longer needs a second checkout or a second venv.

## Status: ROLLED OUT to the whole fleet 2026-05-31 (validated)

The in-process gateway is **live on all three agents** — rocky (hub), natasha
(sparky), bullwinkle (puck/macOS, even on py3.14). Each: `gateway_state=running`,
`slack=connected`, 0 restarts, `mac-hermes-gateway` execs the vendored runtime
from the single mac venv. natasha's agent self-test passed under the new code.
Done by syncing main + `pip install -e .[hermes-gateway]` + swapping the
wrapper's exec line, with auto-revert guards (none triggered).

## Acceptance Criteria

- [x] One venv installs the mac monorepo (which now contains the runtime) with
      the `hermes-gateway` extra — codified in `deploy-mac-fleet.sh:3991`.
- [x] The gateway service runs the in-process entrypoint (`mac-hermes-gateway`)
      from the mac venv — codified in the wrapper (`deploy-mac-fleet.sh:4225`);
      live on all three agents.
- [~] `deploy-mac-fleet.sh` still *clones/patches* upstream (now **vestigial** —
      created but unused) so the existing self-test check keeps passing. Removing
      the clone/patch/separate-venv + updating the self-test is a clean follow-up.
- [ ] Remove `MAC_HERMES_AGENT_DIR` / `_hermes_agent_dir_info` + the
      `hermes_startup` string-surgery shims (now dead — the vendored gateway
      calls `mac.agent_provider`). Couple with removing the vestigial clone.

## Notes

The single most fragile deploy step (clone pristine upstream + patch +
runtime string-surgery + second venv) is no longer on the live path. The
remaining vestigial cleanup is low-risk and non-blocking.
