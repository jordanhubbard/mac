# Single-venv deploy: stop cloning upstream Hermes; retire MAC_HERMES_AGENT_DIR

**ADR 0001 stage 4.** With the runtime vendored (hu-02) and imported in-process
(hu-03), the deploy no longer needs a second checkout or a second venv.

## Acceptance Criteria

- [ ] `deploy-mac-fleet.sh` no longer runs
      `git clone ... NousResearch/hermes-agent` nor applies `deploy/hermes/*.patch`.
- [ ] One venv installs the mac monorepo (which now contains the runtime).
- [ ] The systemd `hermes gateway run --replace` unit is replaced by the
      in-process entrypoint (or a mac-owned unit pointing at the monorepo venv).
- [ ] `MAC_HERMES_AGENT_DIR` / `HERMES_AGENT_DIR` and all
      `_hermes_agent_dir_info` filesystem-inspection logic are removed.
- [ ] Fleet self-test verifies the single-venv runtime instead of
      `test -x ~/.mac/hermes-agent/.venv/bin/python`.

## Notes

Removes the single most fragile deploy step. Coordinate with the rollout
runtime-manifest machinery so the digest reflects the unified build.
