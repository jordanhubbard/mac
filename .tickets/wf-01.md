# Draft questions become a real approval gate (binds_to_node, required validation)

**Problem.** `WorkflowDraftService.create_draft()` (`src/mac/workflow_service.py:266`) accepts a `questions` list and an `answers` dict. `approve_draft()` (workflow_service.py:420) → `definition_from_draft()` (workflow_service.py:463) stores them in the compiled workflow's metadata (line 441) but **the runtime never reads that metadata**.

So today: a user filing a draft with `[{"text": "Which DB driver?", "required": true}]` can call `approve_draft()` with empty answers and start the workflow. The questions are a comment field, not a gate.

## Acceptance Criteria

- `approve_draft()` refuses (raises ValidationError) if any question with `required: true` has no matching entry in the draft's `answers` map.
- Each question gains a `binds_to_node` (str, optional) and `binds_to_param` (str, optional) field. When set, the answer is injected into the named node's instructions (or metadata) at compile time so the executor sees the resolved value.
- Each question gains an `id` (str, required, unique within the draft) so answers map by id, not by free-text question content.
- Test: draft with one required unanswered question can't be approved; same draft with the answer supplied compiles successfully and the node payload contains the resolved value.
- Backfill: existing drafts without `id` get one assigned at first read; existing answers keyed by text get migrated best-effort.
