# Keystone: own the per-agent provider decision in-process (delete string-surgery intent)

**ADR 0001 stage 1.** Replace the *intent* of the runtime string-surgery shim
(`hermes_startup._apply_gateway_runtime_shim`, which rewrites upstream
`gateway/run.py` as text) with first-class, tested mac code.

The shim is the mechanism that puts each agent on a different model family
(anti-"agent monoculture"). When upstream drifts, its exact-string needle
silently misses, the override never applies, and nothing in the agent runtime
can explain why — the "inexplicable provider behavior" dark spot.

## Acceptance Criteria

- [x] `src/mac/agent_provider.py` resolves the provider override from the same
      env precedence as the shim, as pure stdlib code (no Hermes import).
- [x] Produces the override contract the gateway needs
      (`override_kwargs` layered onto Hermes' `resolve_runtime_provider` dict).
- [x] Emits a **secret-free** legible decision + rationale; api key never leaks.
- [x] `record_provider_decision` writes a `hermes.provider.resolved` event to
      the `hermes` observability layer, attributable to the agent.
- [x] Surfaced in the `/startup/hermes` report (`runtime.provider_decision`).
- [x] Unit tests green (`tests/test_agent_provider.py`, 12 tests); full
      contract suite green (651).

## Status (2026-05-30)

Shipped. See `docs/adr/0001-unify-hermes-runtime-into-mac.md` and
`src/mac/agent_provider.py`. The owned module is the destination the vendored
gateway will call directly (hu-03), at which point the shim is deleted.
