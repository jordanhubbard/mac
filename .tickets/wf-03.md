# Pre-supplied approval decisions on workflow start (unattended runs)

**Problem.** Today a workflow with N approval nodes stops N times; a human must be on hand to set each `approval_decision`. There is no way to say "I've already thought about this — here are my answers; run it unattended."

## Acceptance Criteria

- `POST /workflows/{workflow_id_or_slug}/start` accepts a new optional body field `pre_decisions: { "<node_key>": "approved"|"rejected", ... }`. The values are stored on the WorkflowRun.
- When the runtime spawns an approval-node task (`workflow_runtime.py:582-613`), it checks the WorkflowRun's `pre_decisions` for a matching `node_key`. If present, the approval-node task is created with `metadata["approval_decision"]` already populated; `tick()` immediately advances along that edge without waiting for human input.
- Pre-decisions are validated at `start` time: every key must match an approval node in the workflow definition, value must be one of {approved, rejected}.
- `start` rejects if a `required: true` question from wf-01 has no answer AND no pre_decisions for any of the approval nodes that depend on that answer.
- CLI: `mac workflow start <workflow> --pre-decision <node_key>=approved --pre-decision <node_key>=rejected`. Multiple uses accumulate.
- Test: start a workflow with all approval nodes pre-decided → it runs end-to-end without intervention, all transitions take the expected edge condition.
