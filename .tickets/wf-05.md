# Workflow UI: graphical chain-of-tasks with color-coded approval gates + question inspector

**Problem.** The Workflows tab in the dashboard (`src/mac/ui/app.ts:1202` `renderWorkflows`, `1315` `workflowGraph`) is functional but barely visual:

- `workflowGraph()` renders only `data.workflows[0]` — a fixed 3-column layout of identical rectangles. No selection, no per-node typing.
- No color-coding for `node_type`. An approval node looks the same as a task / commit / verify node, so a human can't see at a glance "this is where I'm needed."
- The Create Draft form (line 1220) is three `<textarea>` blobs accepting raw JSON for `proposed_steps`, `questions`, `answers`. Users must hand-author JSON to describe questions, with no validation, no linkage to nodes, no shape help.
- The Drafts list (`workflowDraftRecord`, line 1289) shows `Steps`, `Questions`, `Compiled` counts but no way to expand and fill out questions inline.
- There is no double-click affordance, no inspector pane, no run-state overlay.

The workflow API is the system's most leveraged human-AI surface — every other ticket the fleet picks up flows through here — so the UI is the most important user experience to invest in.

## Acceptance Criteria

**Graph rendering**
- Workflow selector (dropdown or list) — the graph reflects the chosen workflow, not arbitrarily `workflows[0]`.
- Auto-layout: rank-based (Sugiyama / layered) DAG layout that handles >5 nodes cleanly. Use [dagre](https://github.com/dagrejs/dagre) or write a small layered layout (no Cytoscape — too heavy for embed).
- Each node renders with: `node_key` (large), `role_required` (small), an icon for `node_type` (task / approval / commit / verify / plan).
- Color-coded by `node_type` *and* state in `styles.css`:
  - **approval** (needs human): warm yellow background, bold border
  - **plan** (wf-04): purple
  - **task** / **commit** / **verify**: neutral blue/green
  - active-run overlay: pulsing border on the current node
  - past nodes: faded; failed nodes: red border

**Inspector / double-click**
- Double-click (or single-tap) on a node opens a side panel inspector (slide-in from the right, not a modal — keep the graph visible).
- For task/commit/verify nodes: shows `instructions`, `role_required`, `max_attempts`, `timeout_minutes`, and (if a run is active) the spawned task with link to its detail.
- For approval nodes: shows the same plus a clear **Decision** form: Approve / Reject buttons with a reason textarea. Submitting calls the existing `approval_decision` metadata path.
- For any node with bound questions (from wf-01 `binds_to_node`): shows each question as a labelled input field (text / radio / select depending on a question's optional `kind` field). Saving updates the draft's `answers`. Required questions are visually flagged.
- Inspector closes via × or click-outside; updates the graph in place.

**Draft creation flow**
- Replace the three JSON textareas with a stepped form:
  1. *Goal* — single textarea (existing).
  2. *Steps* — repeating row, one per proposed_step, with fields: `node_key`, `role_required` (select from known roles), `instructions` (textarea), `node_type` (select).
  3. *Questions* — repeating row, one per question, with fields: `text`, `required` (checkbox), `binds_to_node` (select from this draft's step keys), `binds_to_param` (text, optional). The `id` is auto-generated from text.
  4. *Answers* — auto-rendered question-by-question, only shown for questions whose `required` is true OR have been filled. Updates the draft's `answers` on blur.
- Preview button runs the existing `/workflows/preview` and renders the result inline as a node list (not as raw JSON).
- The Approve button is disabled until all required questions are answered (mirrors the wf-01 enforcement); hovering the disabled state explains why.

**Active-run overlay**
- When a workflow run is selected (new "Runs" sub-tab), the graph highlights the current node and shows past edge traversals as solid arrows, future ones as dashed.
- Pending approval nodes pulse and show a "Decide now" CTA in the inspector.
- Failed/cancelled runs show the failure node in red with the error in the inspector.
- "Pre-decisions" (wf-03) appear as resolved (green) on the graph before the run reaches them.

**Decisions inventory page (wf-02 surface)**
- New sub-route `/ui/workflows/<id>/decisions` (or a "Decisions" tab within the workflow view) showing every approval node as a card with: node_key, instructions, current pre_decision (if any), and Approve/Reject buttons that set the pre_decision. This is the "front-load all human input before starting" entry point.

**Polish & quality bar**
- Keyboard accessible: tab through nodes, Enter to open inspector, Escape to close. ARIA roles on the SVG (`role="img"` + `<title>`/`<desc>`).
- Responsive: graph zooms and pans (pinch / scroll-wheel). The inspector panel collapses to bottom-sheet on narrow screens.
- Consistent with the rest of the dashboard's metric-grid / surface / chip vocabulary (don't introduce a new design language).
- Loading and empty states for every panel.
- E2E test (Playwright or equivalent) walking: load workflow → open approval node → fill question → approve draft → start → observe active run.

## Out of scope

- Editing existing workflow definitions in-place (drafts are the editing surface).
- Drag-and-drop node creation in the graph (the form is the authoring surface; the graph is read+inspect).
- A separate workflow-builder app (this is dashboard-embedded; don't introduce another UI runtime).
