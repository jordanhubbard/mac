# Workflow decisions inventory endpoint + CLI (preview every human gate)

**Problem.** A workflow's "human input" surface is invisible until you actually run it. Approval nodes (`node_type="approval"`) halt at execution time; there's no way to ask the system "given this workflow definition or this active run, list every place a human will need to make a decision."

## Acceptance Criteria

- New endpoint: `GET /workflows/{workflow_id_or_slug}/decisions` returns, for each approval-node, its `node_key`, role required, instructions, and any `binds_to_node` answers already collected from wf-01.
- New endpoint: `GET /workflows/runs/{run_id}/decisions` returns the same view for a live run, additionally including: the current task id (if any), whether `approval_decision` is already set on its metadata, and which downstream edges depend on each decision.
- New CLI: `mac workflow decisions <workflow_or_run_id>` returning the same payload as JSON.
- Doesn't change runtime behavior; this is purely a read endpoint.
- Test: a workflow with 3 approval nodes returns all 3 in the inventory; a run partway through returns the same 3 with one already-decided and two pending.

Blocked by [wf-01](wf-01.md) (the binds_to_node fields are part of the payload). Blocks [wf-03](wf-03.md) (the inventory is what a human consults to populate `pre_decisions`).

## Resolution (2026-05-31)

Implemented + tested (workflow decisions inventory endpoint + CLI).
