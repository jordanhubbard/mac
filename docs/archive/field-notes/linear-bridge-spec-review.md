## Architectural Review

1. **BLOCKER: `TrackerBackend` is not a behavior-preserving Beads retrofit.**  
Spec §7 says "`BeadsBridgeService` and `LinearBridgeService` each implement this protocol" and that the Beads retrofit is "behavior-preserving" ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:228), [docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:233)). Reality: [beads_bridge_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/beads_bridge_service.py:29) is only a narrow `bd` subprocess wrapper with `cli_path()` and `run()` ([beads_bridge_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/beads_bridge_service.py:45), [beads_bridge_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/beads_bridge_service.py:48)). The real bridge is embedded in `ControlPlane`: registration at [services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:7472), polling at [services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:7580), import at [services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9319), writeback at [services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9610). A protocol around `BeadsBridgeService` would miss most actual behavior.

2. **BLOCKER: the proposed protocol is under-shaped for existing Beads semantics.**  
Spec §7 makes `create_issue`, `attach_pr`, and `update_state` first-class backend methods ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:196), [docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:207), [docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:214)). Current Beads-backed imports only bind tasks whose metadata origin is `{"type":"beads"}` and has a `bead_id` ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9416)). Normal Hermes-created tasks are `hermes_interaction` tasks ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:2601)) and `create_task` may only add repository execution metadata, not create a bead ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:2744)). So "beads-backed tenant task creation" is not an existing behavior to route through the same `create_issue` path.

3. **BLOCKER: outbox retry/backoff claims are false.**  
Spec §15.2 says "The outbox already handles retries with exponential backoff and a max-attempt limit" and permanent failures become `dead_letter` ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:623)). Actual schema has only `status`, `attempts`, `created_at`, `processed_at`; no `next_attempt_at`, `max_attempts`, `last_error` column, or dead-letter state ([schema.sql](/Users/vikaspogu/Documents/git-repos/mac/src/mac/data/postgres/schema.sql:206)). `mark_outbox_failed` sets status to `failed`, so it will not be picked up by `list_outbox(status="pending")` ([task_lifecycle.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/task_lifecycle.py:52), [task_lifecycle.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/task_lifecycle.py:82)). Worse, Beads writeback failures are swallowed: `_run_bd_for_task` returns `False` on exceptions ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9549)), `_sync_beads_transition_ledger` ignores that return ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9884)), and the drain marks the row processed if no exception escaped ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:4648)).

4. **BLOCKER: `cp.secrets.upsert` does not exist, and secret dereference is underspecified.**  
Spec §10 calls `cp.secrets.upsert(...)` ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:466)). `SecretsService` exposes `create_secret`, `rotate_secret`, `request_secret`, and `reveal_secret`, not `upsert` ([secrets_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/secrets_service.py:64), [secrets_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/secrets_service.py:131), [secrets_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/secrets_service.py:99), [secrets_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/secrets_service.py:170)). The table also has `name TEXT NOT NULL UNIQUE` ([schema.sql](/Users/vikaspogu/Documents/git-repos/mac/src/mac/data/postgres/schema.sql:518)), so repeated auto-register using create would fail unless the design explicitly does get-or-rotate. Also, bridge-side plaintext access cannot simply "dereference via secrets_service"; `reveal_secret` requires an audit handle and accessor agent ([secrets_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/secrets_service.py:170)).

5. **MAJOR: auto-register is not race-safe enough for replicas or env drift.**  
Spec §10 says `linear_workspaces.name UNIQUE` makes the loser’s `ON CONFLICT DO UPDATE` a no-op ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:492)). Existing Beads auto-register does the opposite: `ON CONFLICT(name) DO UPDATE` overwrites path/source/project/capabilities/interval/metadata ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:7510)). If Linear mirrors that pattern, divergent env between replicas becomes last-writer-wins. If it truly no-ops, secret rotation and config changes are ignored. The spec needs a config hash, explicit drift finding, and a defined rotation path.

6. **MAJOR: poll/import idempotency is overclaimed.**  
Spec §6 says `UNIQUE(source, external_id)` gives idempotent re-import ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:152)). The index exists ([schema.sql](/Users/vikaspogu/Documents/git-repos/mac/src/mac/data/postgres/schema.sql:678)), but current `import_project_item` does `SELECT`, then `create_task`, then `INSERT project_items` ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:7434), [services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:7442), [services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:7455)). In two replicas, that can create duplicate tasks before one project item insert loses. Linear polling must use a single transaction/upsert, not the existing helper as-is.

7. **MAJOR: `state_map` is too flat for Linear.**  
Spec §9.1 caches `resolve_state_map(...) -> Dict[str, str]` in `linear_workspaces.state_map` ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:331)) and §17 assumes lazy refresh on unknown state ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:693)). Linear workflow state UUIDs are per-team, so a flat `{"Done": uuid}` collides across teams. Lazy refresh also does not catch a renamed state whose old UUID still exists but now means something else operationally. Store per-team mappings keyed by `team_id`, include Linear state type/name/id, and refresh predictably, not only on unknown names.

8. **MAJOR: auth requirements do not match current API behavior.**  
Spec §11 says workspace management requires `admin` and runtime calls require `agent` ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:498)). Current scope routing has no `/bridge` special case, so non-GET bridge routes fall through to generic `write` ([api.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/api.py:943), [api.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/api.py:984)). Existing Beads bridge route handlers do not take a `principal` or enforce tenant/admin in-handler ([api.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/api.py:3779)). Linear needs explicit scope mapping and tenant checks, especially for workspace/secret binding.

9. **MAJOR: plugin changes are incomplete and partly point to the wrong file.**  
Spec §13 says "`plugin/manifest.py` gains `provides_tools`" ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:579)). Actual `provides_tools` lives in [plugin.yaml](/Users/vikaspogu/Documents/git-repos/mac/plugin/plugin.yaml:10), while [manifest.py](/Users/vikaspogu/Documents/git-repos/mac/plugin/manifest.py:41) defines `TOOLS`. Adding tools also requires schemas in [schemas.py](/Users/vikaspogu/Documents/git-repos/mac/plugin/schemas.py:34), and possibly body shaping in [__init__.py](/Users/vikaspogu/Documents/git-repos/mac/plugin/__init__.py:98).

10. **MAJOR: phasing hides required dependencies.**  
Spec §19 puts lifecycle comments in L3 and `TrackerBackend` in L4 ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:757), [docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:767)). But L3 depends on an outbox redesign, backend dispatch, secret plaintext access, idempotency, and API auth choices. L1 also needs migrations in both SQLite and Postgres; current SQLite migrations are private `_ensure_column` calls ([store.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/store.py:1224)), while Postgres uses packaged schema plus public `ensure_column` ([store_postgres.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/store_postgres.py:240), [store_postgres.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/store_postgres.py:257)).

11. **MINOR: Beads drift and ledger details are not quite accurate.**  
Spec §3 names `beads.export_drift.jsonl_only_ready` ([docs/linear-bridge-spec.md](/Users/vikaspogu/Documents/git-repos/mac/docs/linear-bridge-spec.md:54)); current open finding is `beads.export_drift.ready_mismatch`, while `jsonl_only_ready` is only resolved as legacy/old state ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9166), [services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9211)). Spec §9.2 examples use `mac-ledger v1: ...`; actual Beads comments are pipe-delimited with `task=`, `event=`, `actor=`, and fingerprint fields ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9625), [services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:9662)).

**What Is Right**

`integration_findings` is the actual table name ([schema.sql](/Users/vikaspogu/Documents/git-repos/mac/src/mac/data/postgres/schema.sql:724)), and `record_integration_finding` uses it directly ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:3746)). `project_items` really has `UNIQUE(source, external_id)` ([schema.sql](/Users/vikaspogu/Documents/git-repos/mac/src/mac/data/postgres/schema.sql:688)). Secrets are Fernet-encrypted at rest ([secrets_service.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/secrets_service.py:288)). Dolt sync is disabled by default in `_sync_beads_database` ([services.py](/Users/vikaspogu/Documents/git-repos/mac/src/mac/services.py:8409)).

Missing entirely: a tenant deletion story, Linear workspace/secret cleanup, Linear-specific observability taxonomy and metrics, explicit API token/scopes for bridge operations, and a migration ordering plan that keeps SQLite and Postgres aligned.
