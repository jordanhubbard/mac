# Heavy worker admission

`mac admin worker-slot` is the executor-local front end to WebMux's authoritative FIFO queue. It does not create a MAC-side lock. The caller must supply an absolute reviewed WebMux executable, its SHA-256 fingerprint, and the exact registered executor subject. MAC verifies the binary, guide subject, live queue contract, resource identity, capacity, fences, history epoch, and lease expiry before returning a lease receipt.

Use `enqueue` once and retain its ticket ID. `status` and bounded `wait` only observe; queue readiness is not ownership. Use a fresh request ID for each observation and each new acquisition attempt. Before starting the acquisition subprocess, preserve the ORIGINAL acquisition request ID durably: if its response is lost, retry that exact ID to recover the frozen grant and refreshed current proof rather than creating a new attempt. Normalized receipts preserve the validated caller request ID for correlation. Native heavy work may begin only after `acquire` returns a validated current lease. Preserve ticket and lease IDs separately, renew the same fence, and release when work finishes. A duplicate enqueue for the same actor, custodian, and resource may return the original waiting ticket; later lease or deadline values do not replace that ticket's values.

The initial supported resource is `node:<executor-node-id>:heavy` with capacity one and contract `webmux-worker-queue/v1`. The CLI emits only normalized public receipt fields and never child stderr. It fails closed for PATH binaries, identity mismatch, stale or unproven grants, invalid fences, and unsafe expiry.

The registered operator personality exposes this as an intent affordance in its work context. The personality may create or relate the durable MAC task, but it is not a lease proxy: only the provisioned actor named by WebMux `guide` may enqueue and acquire through its executor-local CLI. A missing actor capability is a hard stop. Queue receipts and actual work completion remain separate evidence, and a staged dependent task remains held until a deployed authority canary succeeds.

For personality delivery, `MAC_WORKER_DIRECTABLE_STREAM_IDS` may contain comma-separated exact `bus_...` IDs. When directability is enabled, this filter applies to both peer messages and human directives before dispatch. An empty or malformed configured allowlist denies every stream; an unset variable preserves legacy delivery behavior.
